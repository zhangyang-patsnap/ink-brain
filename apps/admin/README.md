# InkBrain 作者工作台

一个本地优先、单作者的内容后台。管理文章、专题、项目、工具、图片、安装包和站点文案；访客站点仍然是 Astro 静态输出。无需数据库。

## 启动

在仓库根目录执行 `npm install`，然后执行 `npm run admin`。

- 后台：<http://127.0.0.1:4322/admin/>
- 已发布站点：<http://127.0.0.1:4322/>
- 第一次由作者自己设置至少 6 位密码，没有默认密码。重启后重新登录。
- `npm run dev` / 4321 默认跳转至 4322 的已发布站点，须同时启动后台。仅做界面开发时，可用 `INKBRAIN_SOURCE_PREVIEW=1 npm run dev` 查看源码示例；该显式开发模式不展示后台发布数据。

首次启动会把现有 Demo 导入草稿，之后不会自动覆盖草稿。初次正式发布前，4322 首页提示尚未发布。

## 日常使用

1. 在文章、专题、项目或工具中编辑，或点击新建。文章的内部标识自动生成且不会显示；其他内容的标识使用英文小写与短横线，创建后不可更改。
2. 在“标签”中新增标签或修改显示名称。正在被文章使用的标签需先从文章中移除，才能从标签目录删除；标签变更会随下一次发布生成对应的公开标签页。
3. 文章或专题正文可以直接上传本地 HTML、Markdown、PNG、JPG、JPEG 或 WebP，无需先进入文件库。上传的文件会替换当前正文，并立即在编辑器下方展示：HTML 与 Markdown 渲染为正文，图片直接显示。系统会在后台保存一份私有副本，确保预览和发布后的资源地址稳定。文件库只用于管理已有素材和安装包；工具中选择安装包会自动填入下载地址、大小和 SHA-256。
4. 编辑页底部可以“保存草稿”或“保存并发布”。保存并发布会先保存当前内容，再安全构建并切换访客站点。
5. 专题、项目和工具可按需要设置是否发布。专题中的关联内容也需要处于发布状态。
6. 不需要的内容可在对应列表中直接删除，操作前会二次确认。服务端会清理专题引用、重新发布并切换访客站点，完成后才返回删除成功，无需浏览器再发起发布请求。通常需要几秒；更新失败会明确提示，保留上一个正常访客版本。访客 HTML 不缓存，刷新已打开页面即可查看更新。

文件库中的文件也可以直接删除。删除前会二次确认；仍被文章正文、工具安装包或其他草稿内容引用的文件会被拒绝删除，需先移除对应引用。

文章正文以 Markdown 为主并支持代码块，也可导入 HTML。HTML 会经过清理，只保留安全结构，不执行 MDX、脚本、事件属性或危险链接。独立 HTML 中引用的相对资源不会自动导入，图片应单独上传。文章使用标签建立关联，不再设置主题、成熟度、分类或系列。

源代码放在 Git 仓库中，在项目里填写 HTTPS 仓库地址；后台不执行或部署任意源码。文件库支持 UTF-8 HTML/Markdown（最多 2 MB）、PDF、PNG/JPEG/WebP，以及 DMG、ZIP、tar.gz、TGZ、VSIX 安装包（单个文件最多 256 MB）。安装包不做病毒扫描、签名或公证，需要作者发布前自行确认。

## 草稿与直接发布

- 保存使用递增版本号。多个窗口同时修改时，过期保存会被拒绝，避免静默覆盖。
- 每次构建使用隔离的源码副本、内容和资源快照。不修改工作区源码。
- 文件上传后仅作者可访问；被发布内容引用的文件才复制进对应发布版本。
- 发布失败会保留旧站点，已保存的草稿不会丢失。
- 后台不提供独立发布管理、私有预览或回滚界面。
- 发布版本和文件暂不自动清理，注意监控磁盘用量。
- 后台不修改框架实验运行时，也不实现网站访问计数服务。

## 数据与备份

默认目录为仓库根目录 `.inkbrain/`，已从 Git 排除。

| 文件或目录                | 内容                         |
| ------------------------- | ---------------------------- |
| `draft.json`              | 当前草稿与版本号             |
| `history/`                | 保存前的草稿历史             |
| `owner.json`              | 加盐密码哈希，不是明文密码   |
| `assets.json`、`uploads/` | 上传元数据与原始文件         |
| `releases/`               | 构建副本、静态站点和内容快照 |
| `active.json`             | 当前发布版本指针             |

“导出内容备份”仅导出草稿和文件元数据，**不包含二进制文件、密码或发布目录**。完整备份应先停止服务，再复制整个 `.inkbrain/` 到受保护的备份位置；恢复时停止服务并整体恢复该目录。不要把它放入公开静态目录或提交 Git。跨机器迁移建议保留草稿与 uploads，在新机器重新构建（旧版本含本机依赖符号链接）。

## 服务器部署约束

本轮只实现和验证本地服务，未修改线上站点。

需要 Node.js 22.12+、项目依赖、可写持久磁盘以及一个 Node 服务进程。不能仅把此后台部署到静态文件托管平台。仅支持单实例，不能多个进程同时写同一数据目录。

| 环境变量         | 默认值 / 用途                                                                                  |
| ---------------- | ---------------------------------------------------------------------------------------------- |
| `ADMIN_HOST`     | `127.0.0.1`，推荐保持回环地址并由反向代理转发                                                  |
| `ADMIN_PORT`     | `4322`                                                                                         |
| `ADMIN_ORIGIN`   | `http://127.0.0.1:4322`；线上必须设为准确的 HTTPS 来源，如 `https://skarkly.ink`，不含末尾斜杠 |
| `SITE_URL`       | 默认等于后台来源；用于生成 canonical、RSS 和 sitemap                                           |
| `ADMIN_DATA_DIR` | `.inkbrain` 的绝对路径；线上建议独立持久卷                                                     |
| `ADMIN_PASSWORD` | 仅没有作者时使用的初始密码，至少 6 位；从服务的安全环境配置注入，不要写入 Git                  |

反向代理需保留请求 `Host` 与 `Origin`、支持至少 257 MB 请求体，并将 `/admin/` 和公开站点都转发至服务。不要缓存 `/admin/`。上线前先初始化作者，配置 HTTPS、强密码、防火墙和备份，再开放代理；不要将未初始化的后台暴露公网。服务不会信任任意代理头，也没有多用户、邮件找回、自动更新或双因素认证。

会话为内存存储，重启会注销所有会话；Cookie 为 HttpOnly / SameSite=Strict，HTTPS 时启用 Secure。写请求要求准确 Origin 和 CSRF Token。登录失败有速率限制。忘记密码时请先备份并停止服务，通过受控运维流程重建作者配置；本版不提供在线密码找回。

## 验证

执行 `npm run test:admin`、`npm run check`、`npm run build`。

自动测试覆盖未登录访问、来源与 CSRF 拒绝、字段校验、版本冲突、持久化、上传限额、UTF-8 文档校验、HTML/Markdown 安全预览、私有图片重写、私有资源、Markdown 清理、发布失败保护、并发构建拒绝、内容删除，以及清空 Demo 后的真实 Astro 构建。
# Skill 栏目

在后台 **Skill → 新建 Skill** 中手动填写名称、分类、简介、详细说明，并上传文件。

- 来源为「自研」或「引用」，引用必须填写有效 HTTPS 原始链接；不是质量验证状态。
- 支持 `.md` / `.markdown`（UTF-8，最多 2 MB）、`.zip` / `.skill`（最多 256 MB）。压缩包只存储和下载，不解压或执行。
- 上传会生成文件名、大小与 SHA-256。草稿文件保持私有；发布前必须上传，发布时验证内容校验和。
- 保存草稿不会发布；「保存并发布」后出现在 `/skills/`，点击查看进入详情与下载。删除沿用现有同步发布机制。
- 原始 Skill 指令不自动执行，说明由作者手工编写。引用前确认分享许可并保留来源与授权。
- 不扫描或自动同步本机 Skill。新环境包含一个带 MIT 授权的引用 Demo；已有后台只补空的 skills 列表，不自动导入示例或覆盖现有内容。
- 更新代码后，按原启动方式重启后台 Node 进程，再发布。仅刷新浏览器无法加载新的服务端 schema。
