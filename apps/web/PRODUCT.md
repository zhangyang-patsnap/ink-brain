# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

Astro with strict TypeScript, native CSS design tokens, repository-owned Markdown or MDX content, and optional Vue 3 islands only when a future interaction genuinely needs a reactive UI runtime. The stack choice was delegated to and explained by Codex, then accepted by the user.

## Users

InkBrain is primarily authored by a senior backend engineer working across Java, Python, Rust, and AI application frameworks. Its readers are developers who want concise, evidence-aware explanations, runnable experiments when they truly exist, and practical tools without promotional noise.

## Product Purpose

InkBrain is a personal technical publication and navigable knowledge system. It gives technical writing, knowledge domains, framework studies, future independent Labs, and developer utilities one coherent home. Success means a reader can understand the author's focus quickly, follow relationships between topics, and distinguish plans from implemented or verified work.

## Positioning

InkBrain organizes engineering work by both narrative and evidence maturity: articles explain, knowledge entries connect, framework tracks frame experiments, and status language states what has actually been studied, implemented, verified, or used in production.

## Operating Context

The first release is read-oriented, static-first, and repository-owned. The author replaces demo Markdown and typed fixture data with real work over time. Future framework runtimes stay independent from the public web application and communicate only through a documented protocol when implemented.

## Capabilities and Constraints

- Phase one delivers the visual system, responsive page skeletons, typed demo content, navigation, themes, metadata, RSS, and sitemap.
- Demo content must be centralized and replaceable without restructuring pages.
- Feature modules such as runnable Labs, persistent knowledge graphs, and production developer tools remain future work.
- A planned or documented Lab must never be presented as available or verified.
- The public site remains static-first until persistence, credentials, or long-running execution justify a backend.
- The web application must not import framework Lab implementation code.

## Brand Commitments

- Name: InkBrain.
- Voice: concise Chinese reader-facing copy with English identifiers for code and protocols.
- Direction: an editorial technical atlas rather than a generic blog, SaaS dashboard, or neon cyberpunk AI interface.
- The experience must support both light and dark themes without treating dark mode as a simple inversion.

## Evidence on Hand

- Repository architecture and content conventions exist under `docs/`.
- Independent Lab manifests and the shared protocol are documented placeholders only.
- One original abstract knowledge-network image exists at `public/images/inkbrain-knowledge-network.png`.
- All phase-one editorial examples are synthetic demo content and must be labeled accordingly.
- No production case studies, testimonials, user metrics, or live Lab evidence have been supplied.

## Product Principles

1. Show evidence maturity, never imply it.
2. Make relationships between ideas navigable.
3. Keep reading fast and interaction intentional.
4. Let content be replaced without rebuilding the interface.
5. Preserve independent runtime boundaries as the system grows.

## Accessibility & Inclusion

Support keyboard navigation, visible focus, semantic structure, responsive layouts, reduced motion, and WCAG AA contrast for essential text and controls.
