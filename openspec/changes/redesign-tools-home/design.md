## Context

用户已选 A「工具展柜」参考图：大横向主卡与下方三张等宽浅色卡片。当前 tools/index.astro 使用 PageIntro、market-feature 和分散的两个列表。数据已有四类工具，无需 schema 或依赖变更。

## Goals / Non-Goals

**Goals:** 忠实实现参考图的层次、背景和卡片结构；统一分类搜索；适配真实数据、两套主题和手机。

**Non-Goals:** 不重构详情页、不新增在线功能、不编造下载链接、不更改正式发布指针。

## Decisions

- 新建 ToolsHome 组件和 tools-home.css，只替换工具首页。沿用 BaseLayout 的真实页头页脚，不复刻设计稿外框和「设计方案」标签。
- 视觉沿用 paper #f1eee5、paper-deep #e6e0d4、paper-soft #f7f4ec、ink #181714、accent #bd3f29；CLI 用 accent 低比例混色，插件用 success 混色，浏览器用独立冷蓝 #607e99 低比例混色。所有卡片底色基于主题变量，明暗主题保持可读性。标题用既有 display，正文 sans，版本 mono。
- 三列网格首项跨整行，主卡包含大字母图标、分类状态、标题介绍、版本标签和右侧详情按钮；小卡上方图标与介绍、下方分类平台和详情按钮。分类决定淡背景，首项始终石色。小卡不再重复巨大标题或数字编号。
- 分类为全部 / 桌面应用 / 命令行 / 插件。按用户最新要求，组件在静态渲染前排除 web-tool，计数、搜索和空状态也使用排除后的数据；底层记录、类型定义和详情路由不变。各类按数据原顺序保留；分类和搜索取交集，首个匹配项成为主卡。没有结果时提供清除条件，不自动切回全部。
- 查询名称、简介、平台及分类关键词，NFKC 归一化且不区分大小写，多个词全部匹配。输入法 composition 结束才筛选。所有处理本地完成。
- 每项只渲染一次；原生链接保证无 JS 可访问，筛选控制仅初始化后显示；不引入运行时 UI 框架。搜索结果数通过 status 告知读屏。
- 手机为单列主卡与小卡，平板两列，桌面三列；主卡可换行，不裁剪真实长标题/描述。参考文案仅页头采用，不替换工具内容。

## Risks / Trade-offs

- [真实描述比样稿长] → 保留全文、弹性高度、卡片底部对齐，不截断重要状态。
- [过滤后数量不足三张] → 自然保留网格空位，不造示例卡片；单项仍完整主卡。
- [既有全局样式冲突] → 专用类名，截图及 computed layout 验证。
- [用户同时发布] → 只更新隔离预览；不修改 active.json。

## Migration Plan

静态构建即可，无数据迁移；用户确认后按现有后台发布流程上线。回退只需恢复工具首页引用，不影响数据与工具详情 URL。
