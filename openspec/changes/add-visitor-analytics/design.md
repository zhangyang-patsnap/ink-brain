## Context

The visitor footer showed a hardcoded, `DEMO`-labeled visit count, and articles had no view-count concept at all. The admin backend is a single long-lived Node/Express process serving both `/admin` and the published static site out of `ADMIN_DATA_DIR`; there is no database. `auth.mjs` deliberately never trusts proxy headers for its login rate limiter and the project README states the service does not trust arbitrary proxy headers — any new trust of `X-Forwarded-For` must be an explicit, narrowly scoped, opt-in exception that does not weaken that posture.

## Goals / Non-Goals

**Goals:** Real unique-visitor counting for the site total and per-article, no cookies, no client-side dedup logic, real-time display via a public read API, safe-by-default reverse-proxy support.

**Non-Goals:** Precise/marketing-grade analytics, historical trends or dashboards, per-visitor tracking or any durable visitor-linkable storage, admin UI for viewing stats, PV (raw pageview) display anywhere.

## Decisions

- **Dedup key:** `sha256(dailySalt + '|' + ip + '|' + ua)`. The salt is generated fresh in memory on every UTC day rollover and never persisted, so even the hash itself is not stably linkable across days. Only aggregate counts (`totalVisitors`, `articles[id]`) are ever written to `stats.json`; the dedup `Set`s and salt live in memory only and reset when the observed day changes.
- **Accepted limitation:** because dedup state is memory-only, a mid-day process restart forgets who was already counted, so the same visitor can be recounted once after a restart. This is the traded-off cost of never persisting anything visitor-linkable, and is acceptable at this project's scale. Documented in code comments and here rather than solved by persisting hashes.
- **What counts as a visit:** only `GET` requests, with a non-empty User-Agent that doesn't match an obvious bot/script pattern (`bot|spider|crawler|slurp|facebookexternalhit|bingpreview|curl/|wget/|python-requests|go-http-client|headlesschrome`, case-insensitive), whose final response is `200` and `Content-Type` includes `text/html`, and whose path is not under `/admin` or `/api/`. This is checked in a `res.on('finish', ...)` listener so it naturally excludes 404s (including bogus `/writing/<garbage>/` article URLs, which 404 at the static-file layer before any 200 response) and non-HTML assets, without needing a separate "is this a real page" allowlist.
- **Per-article attribution:** the request path is matched against `^/writing/([a-z0-9]+(?:-[a-z0-9]+)*)/$` (aligned with `schema.mjs`'s `slug` pattern) to attribute a visit to an article id in addition to the site total.
- **Proxy trust:** `ADMIN_TRUST_PROXY` (default off) gates whether `X-Forwarded-For`'s last comma-separated entry is trusted as the client IP instead of `req.socket.remoteAddress`. The *last* entry is used — the hop appended by the proxy directly connected to this process — not the first, which is attacker-controlled from the browser side. This mirrors the semantics of trusting exactly one proxy hop. When off (default), the raw socket address is always used, matching `auth.mjs`'s existing posture; this module's trust decision is independent of and does not affect the login rate limiter's IP source.
- **Persistence:** reuses `store.mjs`'s `atomicJson`/`readJson` helpers. Writes are debounced (an unref'd interval flush, default 15s) and serialized through a promise chain — mirroring `server.mjs`'s existing `assetQueue` pattern — so a timer-triggered flush and a shutdown-triggered flush never race on the same file.
- **Public API surface:** a single batch endpoint `GET /api/stats/articles?ids=a,b,c` (1–100 ids, each independently validated against `slug` and silently dropped if invalid/unknown rather than 400ing the whole batch, since this is an anonymous read endpoint where graceful degradation beats strictness) plus `GET /api/stats/summary`. Both set `Cache-Control: no-store` and require no auth/CSRF, since they are anonymous, side-effect-free reads. They live under `/api/*`, not `/admin/api/*`, since they're public rather than author-only.
- **Frontend:** a real-time fetch from a small shared client module (`apps/web/src/lib/visitor-stats.ts`), following the existing pattern of component-scoped `<script>` blocks importing a `src/lib/*` setup function (see `article-toc.ts`, `writing-search.ts`, `mermaid-client.js`). Fails silently on fetch error or non-OK response — this matters because `INKBRAIN_SOURCE_PREVIEW=1` dev mode serves pages with no backend behind them at all.
- **Copy change:** footer label changed from "累计访问" (cumulative visits) to "累计访客" (cumulative visitors), since the displayed number is now UV-deduped, not a raw visit count.

## Risks / Trade-offs

- **Same-network visitors sharing an IP** (e.g. corporate/campus NAT, or any reverse-proxy deployment with `ADMIN_TRUST_PROXY` left off) collapse toward being deduped by User-Agent alone, undercounting distinct people. Documented as an accepted trade-off of avoiding cookies; `ADMIN_TRUST_PROXY` mitigates this for the common single-reverse-proxy case when deliberately enabled.
- **Misconfigured `ADMIN_TRUST_PROXY`** (enabled when the origin is directly reachable, not exclusively behind the trusted proxy) lets any visitor spoof `X-Forwarded-For` to inflate or fabricate counts. Mitigated by defaulting off and documenting the precondition explicitly in `.env.example`/README.
- **Process restarts recount same-day repeat visitors once.** Accepted per the decision above; not solved by persisting hashes, which would be a worse privacy trade-off.
- **UTC day boundary** does not align with any particular visitor's local midnight. Acceptable; not a correctness bug, just means "today" is a UTC calendar day.
